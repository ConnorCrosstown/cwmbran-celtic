**Date:** 2026-05-20
**Auditor:** Claude (Claude Code)

**Repo:** [ConnorCrosstown/cwmbran-celtic](https://github.com/ConnorCrosstown/cwmbran-celtic)

**Scope:** SEO/meta, content accuracy, accessibility, performance, security headers, code review (API routes, data flow, auth, forms), dependency / supply-chain, repo hygiene.

---

## Executive summary

The site is in **decent structural shape** — modern Next.js 16 App Router, strict TypeScript, sensible CSP, JSON-LD structured data, a skip link, semantic landmarks, alt text on every visible image — but it is **not in a launch-ready state**.

The most urgent class of problem is **content/data drift**: the site is serving mock data from a single January snapshot, on top of which UI copy still references promotions (Early Bird closes 31 Jan 2026) and dates (Celtic Bond next draw 25 Jan **2025**) that expired four months ago. Anyone landing on the homepage sees a January match as the "Latest Result" in May.

A close second is **canonical-domain confusion**: every piece of metadata (sitemap, OG tags, JSON-LD, source-of-truth `baseUrl`) points at `cwmbranceltic.com`, which currently 403s. Social shares and search engines will route traffic to a dead address.

A third theme is **security gaps around the staff/admin/newsletter paths**: a `NEXT_PUBLIC_` secret in the client bundle, a hardcoded `'admin-session'` fallback bearer token, no rate limiting on public POST endpoints, defined-but-unused CSRF helpers, and a custom XOR "hash" function being used where `bcryptjs` (already installed) is the obvious answer.

7 npm vulnerabilities (1 critical, 1 high, 5 moderate) — including a Next.js DoS that's fixed in a patch release the project hasn't taken yet.

Counts: **6 P0**, **8 P1**, **10 P2**, **6 P3** — 30 findings.

## P0 — Block launch / live correctness

### P0-1 — Canonical domain (`cwmbranceltic.com`) is dead

- Every reference (`sitemap.xml`, `og:image`, `og:url`-equivalents, JSON-LD `url`/`logo`/`image`, `src/app/sitemap.ts:6` hardcoded `baseUrl`) points at `https://cwmbranceltic.com`.
- `https://cwmbranceltic.com` → 301 to `https://www.cwmbranceltic.com` → **403 Forbidden** (Apache/JustHost via BunnyCDN). Confirmed live.
- The Vercel deployment is effectively an orphan: any organic traffic, social share, or sitemap crawl is routed to the dead domain.
- **Action:** decide whether to (a) repoint the `cwmbranceltic.com` DNS at this Vercel project and add it as a domain in the project, or (b) buy/rebrand. Until that decision lands, set `NEXT_PUBLIC_SITE_URL=https://cwmbran-celtic.vercel.app` and remove the hardcoded `baseUrl` from `src/app/sitemap.ts:6`.

### P0-2 — Homepage data is 4 months stale (mock data only)

- `src/lib/comet.ts` has `USE_LIVE_API = false` and `USE_SOFASCORE = false`. All fixtures/results/league tables fall through to `src/data/mock-data.ts`.
- Live result block shows **Cwmbran Celtic 2-2 Carmarthen Town, 11 Jan**.
- Men's first team listed at **16th, 6 pts, W0 D6 L13** (mid-January standings).
- News carousel headlines are 11 Jan, 6 Jan dates.
- **Action:** provision the `COMET_API_KEY_*` env vars (FAW Comet, listed in `.env.example`) and/or flip `USE_SOFASCORE = true` after wiring the Apify push. Until then the homepage is misinforming visitors.

### P0-3 — Stale, expired call-to-action on `/tickets`

- `/tickets` shows a banner: **"Early Bird Ends 31st January 2026"** — that deadline passed 4 months ago.
- "Super Early Bird — First 50!" still listed as live.
- Adjacent **Celtic Bond** block on `/tickets` shows **"Next Draw: 25th January 2025"** — a year-old date, almost certainly a 2025→2026 typo that was never corrected.
- **Action:** rip the dated CTAs out, replace with current season pricing.

### P0-4 — Match-day pricing contradicts itself

- Homepage "Visit Us" block + footer "Match Day Prices": **Adults £5, Concessions £3, U16 FREE**.
- `/tickets` Match Day section: **Men's £7.50 / £5 / FREE; Women's £3.50 / £2.50 / FREE**.
- These cannot both be right — fans will turn up with the wrong cash. Pick one source of truth (almost certainly the tickets page) and remove or update the homepage / footer values.

### P0-5 — `NEXT_PUBLIC_NEWSLETTER_SECRET` is in the client bundle

- `src/app/admin/newsletter/page.tsx` sends `Authorization: Bearer ${process.env.NEXT_PUBLIC_NEWSLETTER_SECRET || 'admin-session'}`.
- `NEXT_PUBLIC_*` env vars are inlined into the browser bundle by Next.js — anyone viewing source / DevTools can read it.
- Fallback string `'admin-session'` is hardcoded; if the env var isn't set, the secret literally becomes the public string `"admin-session"`.
- Combined with P0-6, an attacker can dispatch newsletters via the public API. The damage is the mailing list address + Resend quota burn + reputational harm of impersonated comms.
- **Action:** rename to `NEWSLETTER_STAFF_SECRET` (server-only — already in `.env.example`!), proxy the admin send through a server action or server-side `/api/newsletter/send` invocation, drop the fallback string.

### P0-6 — `/admin` accessible without auth (client-side gate only)

- `https://cwmbran-celtic.vercel.app/admin` returns 200 to anonymous visitors; the gate is client-only via `localStorage`.
- `src/lib/auth.ts` rolls its own `simpleHash()` (XOR/shift-based) and stores hashed staff credentials in `localStorage`. `bcryptjs` is in `package.json` but not used.
- NextAuth was removed (commit `51bb6ba`) but the package is still a dependency and no server-side replacement was wired in.
- **Action:** put `/admin/*` behind Next.js middleware that checks an httpOnly session cookie, signed with `AUTH_SECRET`. Use `bcryptjs.compareSync` for password verification. Or, given there's only one staff user, swap to Vercel's password-protection feature for the `/admin` segment.

## P1 — High priority

### P1-1 — `next` 16.1.3 has a high-severity DoS, patched in 16.1.5

- `npm audit` flags two CVEs in Next < 16.1.5 (image-optimizer DoS + RSC deserialization DoS).
- **Action:** `npm i next@latest` (16.2.6 at audit time). Same install can bump React to 19.2.6, dompurify to 3.4.5 (closes the XSS CVE), date-fns to 4.2.1, framer-motion to 12.39, resend to 6.12.

### P1-2 — Critical CVE in transitive `basic-ftp` (via Puppeteer)

- `basic-ftp@<5.2.0` path-traversal, CVSS 9.1. Pulled in by Puppeteer.
- Puppeteer is in `devDependencies` so it doesn't ship to prod, BUT — see P1-3 — it's `import`ed at runtime in an API route, which means a build that includes that route will pull production-equivalent code from Puppeteer. Either way, replacing Puppeteer with `@sparticuz/chromium` + `puppeteer-core` (or `@vercel/og` for the actual PDF/og use case) drops the dep tree.

### P1-3 — `/api/programme/pdf` imports `puppeteer` (devDep) at runtime

- `src/app/api/programme/pdf/route.ts:2` → `import puppeteer from 'puppeteer'`.
- Puppeteer is a devDependency. On Vercel's production build, devDeps are pruned; this route will 500 in prod the first time someone hits it.
- It also wouldn't work even if installed — full Puppeteer bundles ~280MB Chromium, exceeding the Vercel function size limit.
- **Action:** swap to `@react-pdf/renderer` (already installed!) or `@vercel/og`. Whatever you pick, move the import out of devDeps.

### P1-4 — Apify/SofaScore webhook auth is weak

- `src/app/api/sofascore/route.ts` accepts secret via either URL query string (`?secret=`) or header. URL secrets end up in logs.
- Simple string equality only — no HMAC of payload, no nonce, no timestamp window. Replay-able indefinitely.
- No rate limit. Any holder of the secret can trigger unlimited data refreshes (Apify quota burn).
- Apify token (`APIFY_API_TOKEN`) is then concatenated into a fetch URL as `?token=...` — also logged.
- **Action:** validate signature header against HMAC of body using `APIFY_WEBHOOK_SECRET`. Drop URL-secret support. Use Apify's `Authorization: Bearer` header instead of putting the token in the URL.

### P1-5 — Newsletter subscribe endpoint has no rate limit

- `/api/newsletter/subscribe` is public POST. Trivially scriptable to spam the list, exhaust Resend quota, or send bulk welcome emails.
- Validation/sanitisation exists (good), but the throttle does not.
- **Action:** add IP-based rate limiting (Vercel KV / Upstash / Vercel Rate Limit middleware — 5/min/IP is fine).

### P1-6 — CSRF helpers exist but no form uses them

- `src/lib/csrf.ts` defines the token mint / verify pair.
- `src/components/newsletter/NewsletterSignup.tsx` (and other forms) POST without sending a token.
- This is a "we did the work then forgot to wire it" gap — quick fix.

### P1-7 — In-memory SofaScore cache is lost on every cold start

- `src/app/api/sofascore/route.ts:23` — `let memoryCache: ... = null;` lives in the function-instance memory.
- Vercel Functions are stateless; on cold start the cache is empty, so the route falls back to disk (`.cache/sofascore-data.json` which doesn't exist in a serverless filesystem) and then to mock data.
- This is why "live data" never actually appears even on routes that try to use SofaScore.
- **Action:** persist in Vercel KV / Redis (Upstash) with the same key shape; existing memory cache can stay as L1.

### P1-8 — OG image canonicalised to dead domain

- `<meta property="og:image" content="https://cwmbranceltic.com/og-image.jpg">` — the image *does* exist on the vercel.app deployment but the meta tag points to the 403 host, so Twitter/Facebook/LinkedIn share previews will fail.
- Same applies to JSON-LD `logo` (`https://cwmbranceltic.com/images/club-logo.webp`) and `image`.
- Fixed automatically once P0-1 is sorted.

## P2 — Medium priority

### P2-1 — `/sponsors/packages` is in the sitemap but 404s
Live status: 404. Sitemap entry: `src/app/sitemap.ts`. Actual route lives at `/sponsors/opportunities`. Crawler & SEO drain.

### P2-2 — `/community/volunteers` is in the sitemap but 404s
Same story.

### P2-3 — `/visit` and `/contact` use the default site title
Both render the homepage default `<title>` because their `page.tsx` files don't `export const metadata`. Visible in tab + bookmarks + search snippets.

### P2-4 — 404 page also uses the default site title
`src/app/not-found.tsx` doesn't export metadata. Browsing to a non-existent URL shows the homepage title; bad for analytics segmentation and confusing for accessibility tools.

### P2-5 — JSON-LD postcode + stadium name don't match the rest of the site
- JSON-LD `streetAddress: "Cwmbran Stadium"`, `postalCode: "NP44 3YS"`.
- Site footer + Visit Us block: "Avondale Motor Park Arena, Henllys Way, NP44 3FS".
- Google Maps pin / "Find us in Search" will land users on the wrong location. Fix the JSON-LD in `src/app/layout.tsx` (or wherever the `<script type="application/ld+json">` block is rendered).

### P2-6 — Dead `next-auth` dependency
Imports purged but `^5.0.0-beta.30` still listed in `package.json:34`. Beta release line, still adds attack surface and bundle weight. Remove.

### P2-7 — Dead `bcryptjs` (and `@types/bcryptjs`)
Either *use* it (in `lib/auth.ts`, replace `simpleHash()`) or remove it. Currently shipping unused.

### P2-8 — Several scrape/headless deps remain in devDependencies but are heavy
`puppeteer`, `playwright`, `jsdom`. Used only by scripts in `/scripts`. Reasonable to keep, but consider whether `npm i -D --no-save` for one-off scrape runs would let you drop them from the committed lockfile (faster CI, smaller surface).

### P2-9 — Sponsor logos rendered via `<img>` not `next/image`
`src/components/sponsors/SponsorCarousel.tsx` uses raw `<img>` tags. Works today because logos are local `/images/players/*.webp`, but bypasses Next.js optimisation (no responsive `srcset`, no AVIF fallback). `next.config.ts` `images.remotePatterns` only allows `comet.faw.cymru` — if any sponsor logo is ever hosted externally, `<Image>` will reject it.

### P2-10 — `meta name="keywords"` is set
Deprecated by Google since 2009, ignored by all major search engines. Won't hurt, but it's noise. Remove from the metadata config.

## P3 — Low priority / nice-to-haves

### P3-1 — Duplicate "Stay Updated" newsletter block on every page
The body has a full-width "Stay Updated" section AND the footer has its own "Stay Updated" block (different visual, same purpose). Pick one — currently visitors see two newsletter prompts back-to-back on the homepage.

### P3-2 — Tickets page "Super Early Bird Adult £65" displayed alongside `£112.50` strikethrough
The presentation in the snapshot reads ambiguously — the `£112.50` shows up next to the live `£65` price; if the strikethrough styling fails (e.g. printed page, screen reader), users will read both numbers as live. Wrap the "before" price in a `<del>`/`<s>` element so the semantics carry without CSS.

### P3-3 — No README in repo
For a public repo (and one that handles emails + tickets + sponsor data), the absence of README/CONTRIBUTING/SECURITY is unusual. Add at least: stack, env vars, "how to run locally", "how to deploy", incident contact.

### P3-4 — `package.json` says `"license": "ISC"` but no `LICENSE` file
Either add a LICENSE file matching that declaration, or change to `UNLICENSED` if the repo is meant to stay closed-source despite being public.

### P3-5 — No CI / GitHub Actions configured
No build check, no `npm audit` in CI, no Dependabot. The vulnerabilities flagged in this audit could have been auto-reported. Recommended minimum: a workflow on `pull_request` running `npm ci && npm run lint && npm run build`, plus enabling Dependabot in repo settings.

### P3-6 — No branch protection on `main`
Currently the only branch; commits go direct. Worth turning on "require PR review" + "require status checks" once CI exists.

### Appendix C — Audit methodology

1. Live-site crawl via `curl` + Playwright (status codes, titles, headers, network, console).
2. SEO/meta inspection via head HTML scrape.
3. Mobile snapshot at 390×844, desktop at 1280×900.
4. Accessibility checks via `page.evaluate()` (alt text, heading order, skip link, button labels).
5. `gitleaks detect` over full repo history.
6. `npm audit --json` + `npm outdated --json`.
7. Source code review delegated to a sub-agent (Read-only) over `src/app`, `src/lib`, `src/components`, configs.
